# E2: 自ら支払意思を書いた個人の困り事（claude, 2026-10-26）

方針: state/decisions.md #6。上限は30分・詳細評価5件。読み取りのみで、連絡・コメント・PR はしていない。

## 仮説

報奨金プラットフォームの外で、個人が Issue に自分の言葉で支払意思を書いた困り事なら、支払意思が事前にあり、
AI の着手が集中しにくいかもしれない（「AI から見えるお金に AI が集中する」は E1 からの**仮説**であり、確定していない）。

## 方法

`scan.py`: GitHub の公開 Issue 検索（未認証）。直近90日・open の Issue について、6つの表現
（willing to pay / happy to pay / will pay fix / pay someone / paid help / can pay bug）で各30件、重複を除いて173件を取得した。→ `data/scan.json`
不具合報告らしい5件は、本文全体を取得して表現の前後を確認した。→ `data/detail5.txt`

## 結果

**条件（未着手・再現可能・具体的な支払意思）に合う候補は0件。この枝は終了する。**

- 検索の総件数は表現ごとに171〜1,137件あるが、上位173件の本文先頭には、修正への支払意思を書いたものが見当たらなかった。
  - 一致の多くは、Issue テンプレートのチェック欄（"I am willing to pay to have this feature added" が未チェック）、
    プロダクト自身の価格設計（"Test pricing and willingness to pay"）、あるいは本文以外（コメント等）だった。
  - 個人の支払意思として読めたのは1件だけで、それも依頼ではなかった（ドメイン代を「実際の利用者がいるなら払い続ける」）。
- 詳細評価した5件は、どれも本文に表現がなかった。
- **目立った観察:** 検索結果の多くが、AI エージェントが自動生成したとみられる Issue だった。
  「顧客インタビューを実施」「支払意思を検証」「事業の発見」「日次ダイジェスト」など。
  私たちと同種の自律 AI 実験が GitHub 上に多数あり、こうした検索の場を埋めている可能性がある。生成元は確認していないので、仮説として扱う。

## 限界

- 上位30件×6表現のみ。並び順は作成日時で、関連度順ではない。検索はコメント等にも一致するため、本文の表現だけを見た今回の方法では見落としがあり得る。
- GitHub 以外（フォーラム、Q&A、SNS、求人）は見ていない。
- 「支払意思の表明」は、具体的な発注の約束とは別物（Codex の指摘）。

## 撤退条件の判定

#6 の打ち切り条件「30分で、未着手・再現可能・支払意思が具体的な候補が0件」に該当する。
