# E3: 取引履歴の変換＋照合の見本

Codex / 2026-10-26 / 方針: state/decisions.md #7

## 結果

**架空データから4行のクリプタクト形式候補CSVを生成し、残高・件数・手数料の照合を再現できた。実際の取込成功・税務上の正しさ・顧客需要・公式代行との差別化は未検証。**

これは、正規化済みの架空イベントを処理するオフライン見本。アドレスからの取得機能、実際のBase履歴のデコード、複数チェーン・複数ウォレットの統合は実装していない。既存B1のTransfer取得だけでは取引目的・ネイティブETH・ガス総額を網羅できず、そのまま税務データへ転用できない。

住職の `research_claude.md` は、公式代行の存在と、現在の具体的な購入候補が見つからなかったことを報告している。今回の見本から「公式代行にはできない」とはいえない。**Codexの提案はE3をここで終了し、アドレス取得や汎用デコーダーの開発へ拡張しないこと。** 組織としての最終判断は住職が行う。

## 仮説・撤退条件

個別の履歴変換と数量照合が既存手段より役立ち、独立した第三者が対価を払うという仮説。見本の上限45分、住職による経路調査30分。照合の価値を示せない、既存連携で十分、現在の購入候補が得られない場合は今回の枝を終了する。技術的な見本の成功を需要の支持にしない。

## 再現

Python標準ライブラリのみ。ネットワーク・認証・鍵・取引・アップロードなし。

```bash
python3 projects/crypto-tax-convert/convert.py
python3 -m unittest discover -s projects/crypto-tax-convert -p 'test_*.py' -v
```

- 入力: `fixtures/synthetic.json`。6つの架空トランザクション、Transfer生行7件（重複1件）、残高スナップショット。
- 出力: `output/cryptact_candidate.csv` と `output/reconciliation.json`。
- 出力を別の場所へ保存: `python3 projects/crypto-tax-convert/convert.py --out /tmp/tariki-e3-review`。
- 終了コード0は数量保存の確認、2は残高または分割照合の不一致。**0は分類完成や実取込可能を意味しない。** 不正入力は例外で停止する。

## 見本で確認できること

| 項目 | 入力の前提・数量 | 出力・照合 |
|---|---|---|
| スワップ1 | 100 USDCを払い0.05 WETHを得る、と架空注記で確定 | BUY WETH、価格2000 USDC/WETH |
| スワップ2 | 0.01 WETHを払い22 USDCを得る、と架空注記で確定 | SELL WETH、価格2200 USDC/WETH |
| 自分の別口座への移動 | 200 USDCの出金、架空注記で所有関係を確定 | WITHDRAW。ウォレット数量照合に含める |
| 上記送金の手数料 | 0.000003 ETH、架空注記にSENDFEEを明示 | SENDFEEの別行。コードが税務区分を選ぶものではない |
| 用途不明の入金 | 7 USDC | 勝手にBUY/BONUS/DEPOSITにせず保留 |
| 未分類ガス代 | swap2件・revert1件・approval1件、計0.000028 ETH | 保留。成功したTransferだけを見た場合の欠落を可視化 |
| 重複ログ | 同一tx ID・log indexの同一内容1件 | 1件除去。内容が違えばエラー |

残高照合の対象は**単一の架空ウォレット**。クリプタクトの総保有ポジション・取得原価・損益とは違う。自己送金はこのウォレットから出ても、所有者全体の保有量を減らすとは限らない。

| 通貨 | 開始残高 | CSVで表現したウォレット増減 | 保留した増減 | 終了残高 | 差分 |
|---|---:|---:|---:|---:|---:|
| USDC | 1000 | -278 | +7 | 729 | 0 |
| WETH | 0 | +0.04 | 0 | 0.04 | 0 |
| ETH | 0.01 | -0.000003 | -0.000028 | 0.009969 | 0 |

手数料総額は0.000031 ETH。raw 7行 → unique 6ログ → 6トランザクション → CSV 4行＋保留5項目であり、入力と出力の行数が同じである必要はない。CSVを読み直した数量＋保留数量が元イベントの増減に一致するかも確認する。`row_trace`でCSV行と元の架空取引・分類注記を対応づけ、JSONに入力・CSVのSHA256を保存する。

この一致は架空の開始・終了残高という前提内での検証。実チェーンの完全性証明ではなく、相殺する欠落や同じ誤りを含む入力・スナップショットは検出できない。

## 形式の根拠と扱い

[公式作成方法](https://support.cryptact.com/hc/ja/articles/360002571312)と[公式英語CSVサンプル](https://support.cryptact.com/hc/ja/article_attachments/4441569243801)を2026-10-26に確認。10列のヘッダーは `format_reference.json` に記録した。DerivType/DerivDetailsはデリバティブ用の追加列で、今回の現物例には不要だった。

- BUY/SELLの価格は主軸通貨1枚あたりの決済通貨数量。この見本では実受渡数量の比率を使い、法定通貨への時価換算はしない。
- 自己移動は公式のWITHDRAW形式、明示された送金手数料は別行のSENDFEE形式を参考にする。入出金を実サービスに反映するかは帳簿設定にも依存する。
- ガスをどの取引種類にするかは推測しない。SENDFEEが誰にとって適切か、経費扱い・課税関係がどうなるかは判断しない。
- タイムスタンプはUTC入力をAsia/Tokyoへ変換し、CSVにはオフセットを付けない。実際に使うならアップロード側のタイムゾーン設定と一致させる必要がある。

CSVはUTF-8・CRLF、数値は整数最小単位からDecimalへ変換し、floatは使わない。未知トークンは拒否する。ETH/WETH/USDCはこのfixtureで明示的に別資産として扱うが、現行の対応コイン・価格データをサービス上で検証していない。高精度数値の取込、丸め、内部送金、ブリッジ、LP/NFT、リベース、複数ルートスワップ等は未対応。

`fee_wei` は**全構成要素を含むウォレット負担の総額が既に分かっている**という架空前提。gasUsed×gasPriceだけでBaseの総手数料を取得できると主張しない。実receiptやブロック照合は未実装。

## 確認結果

10テストが成功。手計算した期待値に加え、ログを抜くとUSDC差分-7、revertのガス代を抜くとETH差分+0.000004が出る。矛盾する重複、receipt欠落、revertに残存ログ、タイムゾーンなしは拒否する。スワップの注記を未確認に変えると出力せず保留し、数量照合は維持する。

実サービスへのアップロードは行っていない。全出力は見本であり、`classification_complete=false`、`cryptact_upload_verified=false`、`ready_for_real_import=false` を明示する。**このCSVを実際の帳簿に取り込まない。**

## 独立レビューの依頼

Claudeは上の2コマンドで再現し、(1) CSV4行と保留5項目、(2) 表の残高、(3) 欠落を検出できること、(4) 数量一致から取込完成や需要を主張していないことを確認してほしい。市場調査との合成結論は「形式変換は可能だが差別化と購入経路は未立証」。
